# 🎵 Windows AirPlay Receiver

**Превращает ваш компьютер в «колонку AirPlay»: включаете музыку на iPhone, iPad или Mac, нажимаете значок AirPlay, и звук играет из динамиков компьютера.**

> ⚠️ **Статус: рабочий, но ранний.** Проверено на связке Windows + iPhone (звук идёт, регулировка громкости работает). Проект написан с нуля на Python и находится на ранней стадии. Он умеет только звук (без картинки), работает по старому протоколу AirPlay 1 и может не подружиться с некоторыми устройствами. Подробности в разделе [«Ограничения»](#-ограничения-читать-обязательно).

## 🤔 Что это такое (простыми словами)

У Apple есть технология **AirPlay**. Она позволяет «отправить» звук с iPhone, iPad или Mac на другое устройство: умную колонку, телевизор, приставку.

Обычно компьютер с Windows так делать не умеет. Он не появляется в списке AirPlay-устройств.

**Эта программа исправляет это.** Вы запускаете её на компьютере, и он появляется в списке AirPlay на вашем телефоне под выбранным именем. Выбираете его, и звук идёт из колонок или наушников компьютера.

Примерно так:

```
   ┌──────────────┐   по Wi-Fi    ┌─────────────────────────┐
   │ iPhone / Mac │ ────────────► │ Компьютер с этой        │ ──► 🔊 Колонки
   │ (играет      │               │ программой              │     или наушники
   │  музыку)     │               │ (получает и воспроизводит)│
   └──────────────┘               └─────────────────────────┘
```

## 🚀 Быстрый старт для новичков

Ниже два способа. **Способ 1 проще**, если у вас уже есть готовый `.exe`. Если его нет, используйте способ 2 или [соберите `.exe` сами](#-как-собрать-свой-exe-файл).

### Способ 1: у меня есть готовый `WindowsAirPlay.exe` (приложение с окном)

1. Положите `WindowsAirPlay.exe` в любую папку, например `C:\AirPlay`.
2. Дважды кликните по нему. Откроется окно приложения, статус сразу станет **«Работает»** (зелёная точка).
3. Windows спросит про брандмауэр. Нажмите **«Разрешить доступ»**. Обязательно отметьте **«Частные сети»**.
4. Название устройства, выбор колонок, автозапуск с Windows и журнал находятся прямо в окне (см. [«Приложение с окном»](#️-приложение-с-окном)).
5. Если закрыть окно крестиком, приложение **не выключается**, а прячется в трей (значок рядом с часами). Выйти совсем можно через правый клик по значку → **Выход**.
6. Переходите к разделу [«Как подключиться»](#-как-подключиться-с-iphone--mac).

> Есть и консольная версия `AirPlayReceiver.exe`, она показывает подробный текстовый журнал и удобна для поиска проблем (`AirPlayReceiver.exe --debug`).

### Способ 2: запуск из исходного кода

#### Шаг 1. Установите Python

1. Откройте https://www.python.org/downloads/ и скачайте **Python 3.11 или 3.12**.
2. Запустите установщик.
3. ⚠️ **Очень важно:** внизу первого окна установщика поставьте галочку **«Add Python to PATH»**, и только потом жмите «Install Now». Если забудете, дальнейшие команды не сработают.

#### Шаг 2. Скачайте проект

На странице проекта нажмите зелёную кнопку **Code → Download ZIP**, распакуйте архив в папку, например `C:\AirPlay`.

В папке должны лежать файлы:
```
airplay_audio.py
airport_key.pem
requirements.txt
build_exe.bat
README.md
```

#### Шаг 3. Откройте командную строку в этой папке

Зайдите в папку в проводнике, кликните в адресную строку (где написан путь), сотрите путь, напечатайте `cmd` и нажмите **Enter**. Откроется чёрное окно, уже «стоящее» в нужной папке.

#### Шаг 4. Установите нужные библиотеки (один раз)

Вставьте в чёрное окно и нажмите Enter:

```
pip install -r requirements.txt
```

Подождите, пока всё скачается.

#### Шаг 5. Запустите

```
python airplay_audio.py "Мой AirPlay"
```

Текст в кавычках — это **имя**, под которым ваш компьютер появится на телефоне. Можно запустить и без него: программа сама спросит имя и запомнит (см. [«Как изменить название»](#️-как-изменить-название-устройства)).

Вы увидите строку «запущен… (с ключом)». Теперь разрешите доступ в брандмауэре (как в способе 1, пункт 3) и переходите дальше.

## 🖥️ Приложение с окном

Окно приложения показывает всё важное и позволяет менять настройки без командной строки.

| Что в окне | Для чего |
|---|---|
| **Статус** (цветная точка) | Серая — остановлен, зелёная — работает и ждёт подключения, синяя — сейчас играет с вашего устройства (с его названием) |
| **Запустить / Остановить** | Включает и выключает приёмник. Когда он остановлен, компьютер пропадает из списка AirPlay |
| **Название устройства** | Впишите имя и нажмите «Сохранить». Приёмник сам перезапустится с новым названием |
| **Куда выводить звук** | Список колонок и наушников. «По умолчанию» — те, что выбраны в Windows; в этом режиме приложение само переходит на новое устройство, если вы переключили вывод в Windows или в FxSound. Кнопка **⟳** перечитывает список (например, после подключения наушников) |
| **Задержка звука** | Три режима. **Минимальная** (≈0,2 с): пауза, старт и смена роликов реагируют быстрее всего, нужен ровный Wi-Fi. **Обычная** (≈0,25 с): баланс, включена по умолчанию. **Надёжная** (≈0,65 с): звук не прерывается даже на слабом Wi-Fi, но реакция медленнее. Меняется на лету. Буфер **адаптивный**: если звуковая карта осталась без данных (слышен треск), приложение само увеличивает запас и пишет в журнал «Wi-Fi неровный: буфер звука увеличен до N мс»; в стабильной сети запас потом снова уменьшается |
| **Громкость на телефоне** | Показывает положение ползунка громкости на iPhone |
| **Запускать вместе с Windows** | Приложение само стартует при входе в систему (свёрнутым в трей) |
| **При закрытии сворачивать в трей** | Крестик прячет окно, музыка продолжает играть |
| **Журнал** | Кто подключился, что случилось, какие были ошибки |

**Значок в трее** (рядом с часами): двойной клик или «Открыть окно» показывает окно, пункт «Остановить/Запустить» управляет приёмником, «Выход» закрывает приложение полностью.

**Устойчивость.** Если телефон пропал без «до свидания» (выключили Wi-Fi), соединение закрывается само в течение нескольких секунд. Если изменился IP-адрес компьютера (Wi-Fi переподключился, ноутбук проснулся), приёмник сам обновляет объявление в сети. Если название уже занято другим устройством, к нему добавится номер, например «Кухня (2)». Идентификатор приёмника создаётся один раз и запоминается, поэтому iPhone не считает его новым устройством после каждого запуска.

**Одна копия.** Приложение запускается только в одном экземпляре. Если запустить его ещё раз (например, пока оно спрятано в трее), просто откроется окно уже работающей копии.

**Если порт 5000 занят** другой программой, приёмник сам выберет свободный порт и напишет об этом в журнале. На работу это не влияет: телефон узнаёт порт автоматически. Консольную версию (`AirPlayReceiver.exe`) одновременно с приложением запускать не нужно: они будут конфликтовать из-за одного и того же названия устройства.

## 📱 Как подключиться с iPhone / Mac

> Телефон (или Mac) и компьютер должны быть **в одной Wi-Fi сети** (в одном роутере). Если телефон в мобильной сети или в гостевой Wi-Fi, ничего не получится.

### iPhone / iPad

1. Запустите приёмник на компьютере (чёрное окно должно быть открыто).
2. Включите музыку (Apple Music, YouTube, Spotify, любой плеер).
3. Откройте **Пункт управления** (свайп вниз от правого верхнего угла; на старых iPhone — свайп вверх снизу).
4. Нажмите на значок **AirPlay** в плеере (кружок с треугольником) или на значок рядом с названием трека.
5. В списке выберите имя вашего компьютера (например, «Мой AirPlay»).
6. Звук пойдёт из колонок компьютера. 🎉

### Mac

1. Нажмите значок звука в строке меню (справа вверху). Если его нет: **Системные настройки → Звук**.
2. В списке выходов выберите имя вашего компьютера.

## ✏️ Как изменить название устройства

Название — это то, как компьютер выглядит в списке AirPlay на телефоне.

**В приложении с окном:** впишите новое имя в поле «Название устройства» и нажмите **«Сохранить»**. Приёмник перезапустится сам.

**В консольной версии:**

- **При первом запуске** программа сама спросит:
  ```
  Как назвать это устройство в списке AirPlay?
  Название [Windows AirPlay]:
  ```
  Впишите имя (например, `Колонки в гостиной`) и нажмите Enter. Если просто нажать Enter, останется «Windows AirPlay».
- Имя **запоминается** и в следующие разы спрашивать не будет.
- **Чтобы сменить имя**, запустите с флагом `--rename`, и вопрос появится снова:
  ```
  AirPlayReceiver.exe --rename
  ```
- Или задайте имя сразу (оно тоже сохранится):
  ```
  AirPlayReceiver.exe "Кухня"
  ```
  Из исходников: `python airplay_audio.py "Кухня"`.
- Имя сохраняется в файле `%APPDATA%\WindowsAirPlay\config.json`. Удалите его, чтобы сбросить имя.
- Ограничения: до 50 байт (около 25 русских букв), точки заменяются пробелами.
- Новое имя вступает в силу **после перезапуска** программы. Телефон иногда пару минут показывает старое имя из кэша: выключите и включите Wi-Fi на телефоне.

## 🛠 Если что-то не работает

Сначала посмотрите на **чёрное окно**. Программа сама пишет, что происходит. Строки с пометкой `[RTSP]` и `[диагностика]` — это подсказки.

### Проблема 1. Компьютер не появляется в списке AirPlay

Проверьте по порядку:

- [ ] Чёрное окно с программой открыто и написано «запущен».
- [ ] Телефон и компьютер **в одной Wi-Fi сети**.
- [ ] Вы нажали «Разрешить» в окне брандмауэра Windows и отметили **«Частные сети»**.
- [ ] Сеть в Windows названа **«Частной»**, а не «Общедоступной». Проверить: *Параметры → Сеть и Интернет → Wi-Fi → ваша сеть → Тип сетевого профиля → «Частные»*.
- [ ] Антивирус или VPN не блокируют соединения (временно выключите и проверьте).
- [ ] Попробуйте выключить и снова включить Wi-Fi на телефоне.
- [ ] Некоторые роутеры блокируют общение устройств между собой («изоляция клиентов» или «AP isolation»). Отключите эту опцию в настройках роутера.

### Проблема 2. Компьютер в списке есть, но звука нет

Включите музыку на телефоне, подождите секунд 10 и посмотрите на строки `[диагностика]` в чёрном окне:

| Что написано в окне | Что это значит | Что делать |
|---|---|---|
| Нет ни одной строки `[RTSP]` | Запросы от телефона не доходят до программы | Проверьте брандмауэр и тип сети (см. выше) |
| Есть `[RTSP] OPTIONS`, и дальше ничего | Телефон отказался продолжать (часто из-за отсутствия ключа) | Убедитесь, что в первой строке написано **«с ключом»**. Файл `airport_key.pem` должен лежать рядом с программой |
| `принято пакетов: 0` | Звук до компьютера не доходит (UDP заблокирован) | Разрешите программе доступ в брандмауэре для **частных и общедоступных** сетей |
| Пакеты идут, но `воспроизведено: 0` и есть `ошибка декодера ALAC` | Не получается расшифровать или распаковать звук | Откройте Issue и приложите текст ошибки |
| `воспроизведено` растёт, но звука не слышно | Звук идёт не на то устройство или слишком тихо | Смотрите строку `вывод звука на: ...`. Если там не ваши колонки, выберите правильные как «устройство по умолчанию» в настройках звука Windows. Проверьте громкость на телефоне и в Windows |

### Проблема 3. Звук щёлкает и прерывается

Скорее всего, слабый Wi-Fi. Подойдите ближе к роутеру или подключите компьютер к роутеру кабелем. В программе пока нет повторного запроса потерянных пакетов, поэтому каждая потеря слышна.

### Проблема 4. Телефон показывает «Не удалось подключиться»

Закройте программу (Ctrl+C в чёрном окне), запустите заново и попробуйте ещё раз. Если не помогло, пришлите нам вывод чёрного окна (см. [«Как сообщить об ошибке»](#как-сообщить-об-ошибке)).

### Проблема 5. Переключил устройство вывода (в Windows, FxSound и т. п.), а звук остался на старом

- Оставьте в приложении **«Устройство по умолчанию»**: тогда оно заметит переключение (примерно за 2 секунды) и перейдёт на новое устройство. В журнале появится строка «Устройство по умолчанию изменилось».
- Если выбрано конкретное устройство, звук будет идти именно на него. Выберите другое в списке, и звук **переключится сразу**, прямо во время воспроизведения, без нового подключения. Чтобы обойти FxSound, выберите в списке не его, а свои колонки или наушники напрямую.
- Нажмите **⟳** рядом со списком, чтобы обновить его (нельзя во время воспроизведения).
- В журнале строка **«Звук выводится на: …»** показывает, какое устройство используется сейчас.
- Строка **«Ошибка вывода звука … MME error 6»** при переключении вывода в FxSound — это нормально: драйвер на мгновение пропал, приложение сразу переоткрывает вывод и звук возвращается. Если пауза заметно дольше пары секунд, включите в окне галочку **«Подробный журнал (для диагностики)»**: в журнале появится «поток открыт за N с», и по этому числу видно, что тормозит. Консольная версия: флаг `--debug`.
- Если используете FxSound или другой виртуальный эквалайзер: он сам должен направлять звук на выбранную в нём колонку. Выбор «по умолчанию» в нашем приложении означает «то, что Windows считает основным устройством» (обычно это и есть FxSound).

### Проблема 6. Пауза, старт и смена роликов (Reels, TikTok) срабатывают с задержкой

- Откройте в приложении список **«Задержка звука»** и выберите **«Минимальная»**. Если появятся щелчки или обрывы, вернитесь на «Обычную»: значит, Wi-Fi не справляется.
- Как это работает: при паузе, перемотке или смене ролика iPhone присылает команду «сбросить всё» (`FLUSH`). Приёмник тут же выбрасывает накопленный звук, обрывает буфер звуковой карты и не пускает в новый ролик запоздавшие пакеты от предыдущего. Новый звук начинается после небольшого предбуфера (≈0,08 с в минимальном режиме, ≈0,16 с в обычном, ≈0,5 с в надёжном).
- **Искажения или треск в «Минимальной»:** значит, ваша сеть или звуковое устройство не успевают за маленьким буфером. Приложение само увеличит запас (смотрите строки «Wi-Fi неровный…» в журнале), но если треск не уходит, выберите «Обычную».
- **Контроль задержки:** если из-за дрейфа часов телефона и звуковой карты или заминок сети очередь звука со временем растёт, приложение незаметно сбрасывает лишнее: сначала в тихих местах, а при сильном отставании делает один небольшой перескок вперёд.
- **Диагностика:** включите галочку **«Подробный журнал (для диагностики)»** в окне (в консольной версии флаг `--debug`): раз в 3 секунды в журнале будет строка с текущим буфером, очередью, скоростью пакетов и счётчиком опустошений. Кнопка **«Копировать»** над журналом кладёт весь журнал в буфер обмена, кнопка **«Папка»** открывает папку с файлами `app.log` (то же самое, что в окне), `crash.log` и `config.json`.
- Часть задержки не зависит от приложения: Wi-Fi, сам iPhone и FxSound (его обработка добавляет десятки миллисекунд). Если пользуетесь FxSound и важна минимальная задержка, выберите в списке устройств свои колонки или наушники напрямую.
- Приложение сообщает источнику реальную задержку приёма (заголовок `Audio-Latency`), поэтому в разных режимах она отличается. Источник может использовать это число для синхронизации звука с видео.
- Консольная версия: `AirPlayReceiver.exe --latency min` (или `normal`, `safe`).

### Проблема 7. Приложение не запускается или закрылось само

У приложения с окном нет консоли, поэтому сведения об ошибках записываются в файл **`%APPDATA%\WindowsAirPlay\crash.log`** (вставьте этот путь в адресную строку проводника). При сбое на старте появится окно с этим путём. Приложите содержимое файла к Issue.

Другие файлы в этой же папке: `config.json` (название, устройство вывода, задержка и постоянный идентификатор приёмника). Если iPhone «запомнил» приёмник странно или нужно начать с чистого листа, закройте приложение и удалите `config.json`.

### Проблема 8. Видео на ускоренной скорости (или при загруженной сети) рассинхронизируется со звуком

AirPlay 1 передаёт звук по UDP, и при нехватке Wi-Fi часть пакетов теряется. Приёмник с этим справляется так:
- **Просит источник повторить** потерянные пакеты (стандартный запрос RAOP). Телефон присылает их обратно, и дырка закрывается.
- **Не ждёт** пропавший пакет дольше ~40 мс: пропускает его, а на его место ставит тишину. Раньше приёмник ждал каждый пакет отдельно, и при потерях звук всё сильнее отставал от видео.
- Если Wi-Fi теряет много пакетов, в журнале появится строка «**Wi-Fi теряет около N% пакетов звука**». Это сигнал, что проблема в сети, а не в приложении: приблизьтесь к роутеру, используйте диапазон 5 ГГц, закройте на телефоне фоновые загрузки.
- В подробном журнале в строке статистики есть `повторов запрошено/получено`: если «получено» заметно меньше «запрошено», телефон не успевает отвечать на запросы.

## 📦 Как собрать свой .exe файл

Готовый `.exe` удобен тем, что на компьютере не нужен установленный Python. Есть два способа.

### Способ А: в облаке GitHub (ничего ставить не нужно)

1. Выложите проект на GitHub (все файлы, включая папку `.github`).
2. Откройте вкладку **Actions → Build Windows exe → Run workflow**.
3. Через 3–5 минут внутри завершённого запуска появится файл **WindowsAirPlay** (в разделе *Artifacts*). Скачайте его: в ZIP-архиве лежат `WindowsAirPlay.exe` (приложение с окном) и `AirPlayReceiver.exe` (консольная версия).
4. Чтобы `.exe` автоматически попадал в раздел **Releases**, создайте тег версии (например, `v1.0`): сборка запустится сама.

### Способ Б: у себя на компьютере

1. Положите в одну папку: `app.py`, `airplay_audio.py`, `icon_art.py`, `icon.ico`, `airport_key.pem`, `requirements.txt`, `build_exe.bat`.
2. Установите Python (см. [Шаг 1](#шаг-1-установите-python)).
3. Дважды кликните **`build_exe.bat`**.
4. Подождите несколько минут. Скрипт сам установит библиотеки и [PyInstaller](https://pyinstaller.org/).
5. Готовые файлы в папке `dist`: **`WindowsAirPlay.exe`** (с окном) и **`AirPlayReceiver.exe`** (консольная). Ключ уже упакован внутрь.

> 💡 Антивирусы иногда ругаются на любые `.exe`, собранные PyInstaller. Это ложное срабатывание. Проект открытый, вы можете прочитать весь код и собрать файл сами.

Если сборка не удалась, внизу окна будет надпись `BUILD FAILED`. Скопируйте текст выше неё и приложите к Issue.

## 🔧 Как это работает внутри (для разработчиков)

Реализован приёмник **AirPlay 1**, он же **RAOP** (Remote Audio Output Protocol). Работает в одном процессе на `asyncio` плюс один поток воспроизведения.

### Этапы подключения

```
 Источник (iPhone)                         Наш приёмник
        │                                        │
        │  ── mDNS: ищу _raop._tcp ───────────►  │  (zeroconf объявляет сервис)
        │                                        │
        │  ── TCP :5000  RTSP OPTIONS ─────────► │
        │     (Apple-Challenge)                  │
        │  ◄── 200 OK + Apple-Response ───────── │  (подпись RSA-ключом)
        │                                        │
        │  ── ANNOUNCE (SDP: ALAC, ключ AES) ──► │  (расшифровываем AES-ключ RSA-OAEP)
        │  ◄── 200 OK ────────────────────────── │
        │                                        │
        │  ── SETUP (порты клиента) ───────────► │
        │  ◄── 200 OK (наши UDP-порты) ───────── │  (audio / control / timing)
        │                                        │
        │  ── RECORD ──────────────────────────► │
        │  ◄── 200 OK ────────────────────────── │
        │                                        │
        │  ═══ UDP RTP: зашифрованные ALAC ════► │  → AES-CBC → ALAC → PCM → 🔊
        │                                        │
        │  ── SET_PARAMETER volume: -12.5 ─────► │  (громкость)
        │  ── FLUSH / TEARDOWN ────────────────► │
```

### Ключевые детали

- **Обнаружение:** сервис `<MAC>@<Имя>._raop._tcp.local.`, порт 5000. В TXT-записях объявляются: `cn=0,1` (PCM и ALAC), `et=0,1` (без шифрования и RSA), `sr=44100`, `ss=16`, `ch=2`, `tp=UDP`.
- **Проверка Apple-Challenge:** клиент присылает 16 случайных байт. Ответ: `challenge + IP сервера + MAC (6 байт)`, дополнено нулями до 32 байт, затем «сырая» подпись RSA с отступом PKCS#1 v1.5 тип 1, результат в base64 без `=`.
- **Расшифровка ключа потока:** в `ANNOUNCE` приходит `a=rsaaeskey` (AES-ключ, зашифрованный RSA-OAEP/SHA-1) и `a=aesiv`.
- **Аудиопакеты (UDP):** заголовок RTP 12 байт (тип `0x60`, номер пакета big-endian). Полезная нагрузка зашифрована AES-128-CBC. Шифруются только целые блоки по 16 байт, хвост передаётся открытым. IV сбрасывается для каждого пакета.
- **Декодер:** PyAV (`alac`). Параметры берутся из `a=fmtp` и собираются в 36-байтный «magic cookie», который ожидает FFmpeg.
- **Буферизация:** словарь пакетов по расширенному (развёрнутому) номеру, предбуфер около 60 пакетов (около 0,5 с). Потерянный пакет заменяется тишиной. При опустошении буфера он копится заново.
- **Громкость:** `SET_PARAMETER volume: X` (от −30 до 0 дБ, −144 = выключено), применяется как множитель `10^(dB/20)` к 16-битным сэмплам.

### Чего нет в реализации (хорошие места для вклада)

- Запрос повторной передачи потерянных пакетов (`0x55`) по control-порту.
- Ответы на timing-запросы (NTP-подобная синхронизация) и точная привязка воспроизведения к часам источника.
- Разбор метаданных (DAAP/DMAP в `SET_PARAMETER`): название, исполнитель, обложка.
- AirPlay 2 (HomeKit pair-setup/verify, PTP, буферизованный поток), для этого придётся заметно расширять проект.

## ⚠ Ограничения (читать обязательно)

- **Только звук** и только AirPlay 1. Видео и зеркалирование экрана не поддерживаются и в ближайшее время не планируются: они защищены гораздо сложнее.
- **Современные источники иногда требуют AirPlay 2.** Если приложение настаивает на AirPlay 2, подключение может не получиться.
- **Нет точной синхронизации.** Для музыки это незаметно, а вот для видео со звуком, воспроизводимым этой программой, звук может отставать от картинки. Для фильмов этот способ не подходит.
- **Нет запроса потерянных пакетов.** На слабом Wi-Fi возможны щелчки.
- **Только одно устройство за раз.** Новое подключение вытесняет старое.
- **Проверено слабо.** Проект экспериментальный и протестирован не на всех устройствах и версиях iOS / macOS. Сообщайте о результатах в Issues.
- Основная целевая система: **Windows**. Из исходников на macOS и Linux он теоретически тоже должен запускаться, но это не проверялось.
